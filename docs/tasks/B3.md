Context: continues B1/B2. `scripts/fetch-github-snapshot.mjs` already fetches GitHub data at prebuild with graceful token-less fallback to the committed `public/data/github-snapshot.json`. Extend the pipeline; do not break its existing behavior.

## 2. Verifier — scripts/verify-claims.mjs
- Fetches each claim's repo README (raw.githubusercontent or GitHub API, reuse the request helpers style from fetch-github-snapshot.mjs: timeout, optional GITHUB_TOKEN env, never client-side).
- Each claim: PASS if pattern matches README text, FAIL with a clear message naming the claim id, expected value, and repo if not.
- Behavior matrix:
  - Network + all pass → exit 0, print summary table.
  - Network + any FAIL → exit 1 (build must fail loudly). Print every failure.
  - No network / rate-limited / no token and API refuses → print WARNING "claims unverified — using last verified state", exit 0 (do not brick offline builds), and write `public/data/claims-status.json` with `{ verifiedAt, status: "unverified" }`. On success write `{ verifiedAt, status: "verified", results: [...] }`.
- Wire into package.json: `"verify-claims": "node scripts/verify-claims.mjs"`, and make `prebuild` run snapshot THEN verify-claims.

## 3. Sanitization — lib/github/sanitize.ts
GitHub-originated strings (repo descriptions, names from the snapshot/API) are attacker-influenceable. Add a `sanitizeText(input: string): string` helper: strip control chars, collapse whitespace, hard length cap (300), strip any `<` and `>` characters. Apply it in `lib/github/transform.ts` wherever repo-provided text fields are passed through (description, topics, name). Do not double-escape — React already escapes; the goal is defense-in-depth against markup/control-char smuggling and absurd lengths.

## Hard constraints
- No new npm dependencies.
- Scripts must fail gracefully without GITHUB_TOKEN (warning path above).
- Do not weaken the existing snapshot fallback behavior.
- Finish: `node scripts/verify-claims.mjs` (report its real output), `npx tsc --noEmit`, `npm run lint`. All must pass (verifier may legitimately end in the WARNING path if the sandbox has no network — report which path ran).
